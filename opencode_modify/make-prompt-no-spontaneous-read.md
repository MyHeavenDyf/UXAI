# make/make_plan 提示词：禁止自发性读取本地文件

## 动机

使用较弱模型时，octo_make / octo_make_plan 会自发性调用 `read` 读取当前目录的本地文件（弱模型带编码 agent 习惯，开工作前先"探索环境"），导致无意义的工具调用和权限弹窗。需要在提示词层面约束：**不是不允许读，而是不要自发地读**——仅当用户或 skill 明确给出路径并要求读取时才读。

注意措辞要求（用户反馈）：不要写成"不需要了解项目代码"这类绝对化表述，只强调"不要自发的"。

## 改动文件

| 文件 | 改动内容 |
|------|----------|
| `packages/opencode/src/agent/prompt/octo_make.txt` | ① 「一、输出方式」write/edit 规则后新增 read 规则：不要自发的去读取本地文件，仅当用户或 skill 明确给出路径并要求读取时才读；② 「五、禁止事项」新增：不要自发的读取本地文件或浏览项目目录，未提供的信息直接询问用户 |
| `packages/opencode/src/agent/prompt/octo_make_plan.txt` | ① 「能力边界」read 描述收紧：只读用户在对话中明确给出的文件，不要自发的去读取其他本地文件；② 「强制规则」新增第 5 条：不要自发的读取文件，缺信息直接问用户 |

## 关键措辞

octo_make.txt（输出方式）：

```
- read：不要自发的去读取本地文件；仅当用户或 skill 明确给出文件路径并要求读取时，才去读取
```

octo_make.txt（禁止事项）：

```
- 不要自发的读取本地文件或浏览项目目录；用户未提供的信息，直接询问用户即可
```

octo_make_plan.txt（强制规则第 5 条）：

```
5. **不要自发的读取文件**：不要主动去浏览或读取用户没有明确提供的文件；缺什么信息，直接向用户询问。
```

## 未改动权限

`agent.ts` 中两个 agent 的工具权限保持不变（octo_make 的 read 继承 defaults 的 allow；octo_make_plan 为 `read: "ask"`）。本次只动提示词；若弱模型仍频繁乱读，后续可考虑在 agent.ts 收紧 read 权限。
