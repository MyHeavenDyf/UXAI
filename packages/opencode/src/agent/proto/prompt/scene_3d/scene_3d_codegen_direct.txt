# Objective + Process
实现 [TYPE_LIST] 里**每个 type**，每个 type 按顺序输出**恰好两个**代码块（不分析、不规划、不列清单）：

1. `src/3d/managers/component/handlers/<type>/<type>.ts` —— 该 type 的 ComponentHandler（导出 `<type>Handler`，create 返回 THREE.Object3D）。你决定怎么建：
   - `native`：THREE 原语（BoxGeometry / SphereGeometry / CylinderGeometry / ConeGeometry / PlaneGeometry / TorusGeometry）+ Group 组装。**同模型重复实例按数量选型**：① 少量（几十到几百）直接用普通 `Mesh` 循环 `group.add()`，连 InstancedMesh 都不必；② 数百~5万 用原生 `new THREE.InstancedMesh(geometry, material, count)`；③ ≥5万 才用 a3d `InstancedMesh2`。
   - `component`：`import { 类名 } from '../../../../components'` + `const obj = new 类名(toOptions(node))`（照 catalog constructor 签名 new；构造失败 try/catch 回落原生 THREE）。catalog 的 `extends` 字段判挂载方式（Mesh/Group→group.add、Material→mesh.material=）。
   - `model`：`ctx.loadModel('<src>', { castShadow, receiveShadow, clone: { shareMaterial: false } }).then(m => group.add(m))` 异步挂到返回的 group。**clone.shareMaterial:false 必加**。
2. `<type>.group.json` —— 该 type 的**根节点清单**（TreeNode 数组，JSON）。每个根节点 = `{ "id", "parentId", "params" }`，**id 与该 handler 里 `${node.id}` 前缀严格一致**。

**全部 type 按 type 名顺序依次输出：每个 type 先 handler 后 group.json，再下一个 type。最后输出一个 `scene-config.json`。**（如 3 个 type → 恰好 7 个 `## file:` 块：3 对 handler+group + 1 个 scene-config。）

**根节点数量规则**：该 type 有多少个「独立实例」就放多少个根节点（每个根节点 = 一次 create 调用）。单个整体对象 = 1 个根节点（如 `[{ "id": "warehouse-1", ... }]`，handler 内硬编码整体布局）；沿路重复的离散实例 = 每个实例 1 个根节点（如 10 棵树 = 10 个根节点，position 各异，handler 只写单棵树的 create）。**根节点 id 用 `<type>-<序号>`（type 名原样，含下划线保留），如 `heatmap-1`、`steel_roof-1`、`rack-1` 到 `rack-4`。parentId=null（根）。params 含 position（`[x,y,z]` 数组，y=0 贴地），可选 rotation/scale。**

**3. `scene-config.json` —— 场景级配置**（最后一个文件），含 camera / lights / scene 三个 key：
```json
{
  "camera": { "type": "perspective", "position": [8, 7, 10], "lookAt": [0, 1, 0], "perspective": { "fov": 50, "near": 0.1, "far": 1000 } },
  "lights": [
    { "type": "ambient", "intensity": 0.5 },
    { "type": "directional", "intensity": 1.2, "position": [8, 12, 6], "castShadow": true }
  ],
  "scene": { "background": "#1a1a2e", "environment": { "preset": "studio", "intensity": 0.8 } }
}
```
按用户场景请求定相机、灯光、环境。host 会把它填进 live-data.json 的 camera/lights/scene 键。

- **camera.type**：`"perspective"`（默认，透视）或 `"orthographic"`（正交，用于轴测/俯视/产品三视图类需求）。正交只需 `orthographic: { top, bottom }`（left/right 由 host 按画面宽高比自动算），仍给 position/lookAt。
- **lights 六型**（默认 ambient + directional 主光；局部照明才用 point/spot，rectarea 慎用）：
  - `ambient`：`{ "type": "ambient", "intensity": 0.5 }`
  - `hemisphere`：`{ "type": "hemisphere", "intensity": 1, "skyColor": "#...", "groundColor": "#..." }`
  - `directional`：`{ "type": "directional", "intensity": 1.2, "position": [x,y,z], "castShadow": true }`
  - `point`：`{ "type": "point", "intensity": 1, "position": [x,y,z], "distance": 10, "decay": 2 }`
  - `spot`：`{ "type": "spot", "intensity": 1, "position": [x,y,z], "target": [x,y,z], "angle": 0.5, "penumbra": 0.2, "castShadow": true }`（angle 半角弧度）
  - `rectarea`：`{ "type": "rectarea", "intensity": 1, "position": [x,y,z], "target": [x,y,z], "width": 4, "height": 4 }`
- **fog（可选）**：`{ "type": "linear", "color": "#...", "near": 10, "far": 60 }` 或 `{ "type": "exp", "color": "#...", "density": 0.02 }`（指数雾 density 0.01-0.05；linear 更可控）。
- **不写 renderer / controls 键**（渲染审美与交互手感走引擎默认 + 预览面板调参，生成时不管）。

# Output Format（Markdown 代码块，2N+1 个文件）

**绝对约束**：
- **下一个字符必须 `##`，且恰好输出 `2 × type 数 + 1` 个 `## file:` 块**（每个 type 一对：handler + group.json，外加 1 个 scene-config.json），别的一概不输出。

示例（[TYPE_LIST] 给 heatmap + fountain 两个 type，输出恰好 5 块）：

## file: src/3d/managers/component/handlers/heatmap/heatmap.ts
```ts
import * as THREE from 'three';
import type { ComponentHandler } from '../../ComponentManager';
import type { TreeNode } from '../../../../scene/loader';
import { toOptions } from '../base/options';
import { applyOverride, type OverrideSpec } from '../base/override';

const SUB_OVERRIDES: Record<string, OverrideSpec> = {};  // 规则 6：JSON 兼容，初始空
const SUB_SKIP: string[] = [];                            // 规则 7：循环创建点检查
const SUB_ADD: Array<{ cid: string; position: number[]; rotation?: number[]; material?: Record<string, unknown> }> = [];

export const heatmapHandler: ComponentHandler = {
  create(node: TreeNode) {
    const opts = toOptions(node);
    const group = new THREE.Group();
    for (let x = 0; x < 5; x++) {
      for (let z = 0; z < 5; z++) {
        const cid = `${node.id}-cell-${x}-${z}`;          // 语义 __id（规则 3）
        if (SUB_SKIP.includes(cid)) continue;             // 规则 7：cid 后、新建前
        const box = new THREE.Mesh(
          new THREE.BoxGeometry(0.8, 0.5, 0.8),
          new THREE.MeshStandardMaterial({ color: 0x91cf60, roughness: 0.8 }),  // 每实例 new（规则 6）
        );
        box.userData.__id = cid;
        box.userData.__componentType = node.type;
        box.position.set(x - 2, 0.25, z - 2);
        applyOverride(SUB_OVERRIDES, box, cid);           // 规则 6：必调，漏则 patch no-op
        group.add(box);
      }
    }
    for (const add of SUB_ADD) { /* 照主循环单实例建 + applyOverride */ }  // 规则 8
    if (opts.position) group.position.fromArray(opts.position);
    return group;
  },
  delete() { return false; },
};
```

# Constraints
1. **只输出 `## file: <path>` + fenced code block**。无解释、无思考、无自然语言（file 头除外）。**恰好 `2 × 本轮 type 数 + 1` 个块，不输出 index.ts / live-data.json**（host 生成，输出即判失败）。
2. **group.json / scene-config.json 必须是合法 JSON**（双引号 key、无注释、无 trailing comma），且**根节点 id 与 handler 的 `${node.id}` 前缀一致**。host 用它拼 live-data 的该 type 分组 + camera/lights/scene。
3. **handler 契约**：create 返回 Object3D（null=未处理）；根节点 manager 自盖 __id / __componentType / __logicalRoot，handler 不重复盖根；**子对象 handler 自盖 __id + __componentType（不盖 __logicalRoot）**——循环同质子物体每实例必盖语义 __id（`${node.id}-` 起头，严禁硬编码前缀），组件型 Group 内独立材质子 mesh 亦须盖 `${cid}-<部件>` + applyOverride。**详见 {HANDLER_CONTRACT} 规则 3**。
4. **import 路径**（从 `handlers/<type>/<type>.ts`）：`../../ComponentManager`、`../../../../scene/loader`、`../base/options`、`../../../../resources`、`../../../../components`（barrel 导出全部组件类，直接 `import { 类名 }` + `new 类名(opts)`）。**详见 {HANDLER_CONTRACT} import 路径节**。路径层数错 → vite 运行时报错。
5. **implementation 落地**：native 直接 `new THREE.BoxGeometry(...)` + 每实例 `new THREE.MeshStandardMaterial`（勿共享同一 Material 实例）；component 用 `import { 类名 } from '../../../../components'` + `new 类名(toOptions(node))`（构造失败 try/catch 回落原生）；model 用 `ctx.loadModel(src, { clone: { shareMaterial: false } })`（**shareMaterial:false 必加**）。delete 返回值：自建非共享→false，共享资源→true+手动取消订阅。**详见 {HANDLER_CONTRACT} 规则 5/6**。
6. **modify 时**：[CURRENT_HANDLERS] 里该 type 的布局参数**逐字照抄**（columns/rows/scale/position 数组、循环上界、创建点结构、loadModel src），**只改材质相关代码**（加/改 paint 函数）；**已有 paint 函数原样保留只增不改**——改单个实例色 = 加条件分支 `if (cid 后缀匹配) paintNew(rack); else paintOld(rack);`，**else 保留原 paint**。布局参数擅改 = 数量/尺寸/位置漂移，是 modify 重写的高频 bug，务必逐字照抄不动。根节点 id **照抄** [CURRENT_GROUPS] 里的 id（幂等，勿换 id 否则丢编辑历史）。
7. **代码风格**：单引号、2 空格缩进、语句末分号（对齐 3d-templete 既有 handler 风格）。
8. **禁止 Node API + 禁止包名 import**：严禁 `node:module` / `createRequire` / `require()` / `import.meta.filename` / `process.*`（浏览器 vite 不兼容）。引 3d-components 组件类用相对路径 `../../../../components`。
9. **SUB_OVERRIDES / SUB_SKIP / SUB_ADD 骨架**（per-instance 改动/删/加落盘的前提，务必做）：handler 顶部声明三个空骨架（JSON 兼容格式），循环同质子物每实例调 `applyOverride(SUB_OVERRIDES, obj, cid)`（漏调 = patch 静默 no-op），循环创建点加 `if (SUB_SKIP.includes(cid)) continue`，主循环后加 `for (const add of SUB_ADD) { ... }`。**完整骨架 + JSON 兼容要求 + 索引稳定规则详见 {HANDLER_CONTRACT} 规则 6/7/8**。SUB_OVERRIDES/SUB_SKIP/SUB_ADD 内容**必须合法 JSON**（双引号 key、color "#rrggbb" 字符串、无注释、无 trailing comma）。
10. **GLB 物体改色走 edit_code 加 paint(traverse)，不走 SUB_OVERRIDES**：`ctx.loadModel` 加载的 GLB 材质在内部子 mesh，`applyOverride` 只取顶层 material（GLB 是 Group 无 material → 跳过 = no-op）。codegen 生成 handler 时仍照规则 9 加 SUB_OVERRIDES 骨架（供原生 Mesh 子物用），GLB 改色由 edit_code 实现，二者并存不冲突。
11. **全局坐标系自包含**：每个 type 的根节点 position / handler 内坐标都是**绝对坐标**（地图中心=原点）。凡一个 type 要贴着/沿着/环绕/对齐另一物体，直接在 handler 里写死那物体的绝对坐标，不要用名字引用其他 type（你看不到其他 type 的代码）。
